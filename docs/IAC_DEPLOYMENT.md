# IaC deployment flow

This is the code-first path for V1. Terraform creates AWS infrastructure; shell scripts build/push images and apply the Kubernetes resources.

## 1. Prerequisites

Install:

- AWS CLI v2
- Terraform >= 1.9
- kubectl
- Git
- Docker
- `envsubst` (gettext)

Authenticate to the target AWS account and confirm the default/selected profile:

```bash
aws sts get-caller-identity
```

V1 defaults to `us-west-2`.

## 2. Create the DevOps Agent Agent Space and HMAC webhook

Follow [AWS_DEVOPS_AGENT_SETUP.md](AWS_DEVOPS_AGENT_SETUP.md).

Save the **Primary Cloud Source role ARN** and the generated HMAC webhook URL/secret. The secret is intentionally not stored in Terraform state.

## 3. Configure Terraform variables

```bash
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
```

Set at minimum:

```hcl
admin_cidr = "203.0.113.10/32"
```

If the Agent Space already exists, also set:

```hcl
devops_agent_role_arn = "arn:aws:iam::<account-id>:role/<agent-space-primary-source-role>"
```

## 4. Terraform init, plan, apply

```bash
terraform -chdir=terraform init
terraform -chdir=terraform fmt -recursive
terraform -chdir=terraform validate
terraform -chdir=terraform plan -out=tfplan
terraform -chdir=terraform apply tfplan
```

Important implementation details already handled in Terraform:

- the EKS Pod Identity Agent is installed `before_compute`;
- the VPC CNI is installed `before_compute`;
- `aws-node` receives its own Pod Identity role with `AmazonEKS_CNI_Policy`;
- private EC2 worker nodes receive SSM managed-instance permissions;
- CloudWatch Observability uses a dedicated Pod Identity role;
- the Operator gets a separate Pod Identity role;
- incident S3/CloudWatch destinations are pre-created;
- if `devops_agent_role_arn` is set, Terraform creates the read-only EKS access entry and evidence-read policy attachment.

## 5. Configure kubectl

```bash
aws eks update-kubeconfig \
  --region "$(terraform -chdir=terraform output -raw region)" \
  --name "$(terraform -chdir=terraform output -raw eks_cluster_name)"

kubectl get nodes -o wide
kubectl get pods -A
```

All worker nodes should become `Ready`.

## 6. Build and push the Operator image

Normal local build:

```bash
./scripts/build-operator.sh
```

If your workstation/CloudShell does not have enough Docker build space, use the temporary EC2 path described in [EC2_BUILD_SERVER.md](EC2_BUILD_SERVER.md). The EC2 helper pushes the same deterministic tag, so the normal script will detect it in ECR and skip rebuilding it.

## 7. Build and push the demo image

```bash
./scripts/build-demo.sh
```

## 8. Configure the webhook Secret

Export the credentials generated by AWS DevOps Agent:

```bash
export DEVOPS_AGENT_WEBHOOK_URL="https://..."
export DEVOPS_AGENT_WEBHOOK_SECRET="..."
```

Then create/update the Kubernetes Secret:

```bash
kubectl apply -f kubernetes/namespaces/namespaces.yaml
./scripts/configure-webhook.sh
```

The secret values never enter Terraform state.

## 9. Deploy the Operator

Load Terraform outputs and image references by using the normal deployment helper, or apply the components explicitly.

The easiest supported flow is:

```bash
make deploy
```

`make deploy` is idempotent with respect to the Terraform resources and immutable ECR tags. It performs:

```text
terraform init
terraform plan
terraform apply
aws eks update-kubeconfig
build/push Operator image
create webhook Secret
deploy Operator
build/push demo image
deploy demo workload
```

If the Operator image was already pushed from the temporary EC2 builder, the build script sees the immutable ECR tag and skips the rebuild.

## 10. Watch the OOM failure

```bash
make watch
```

Expected result:

```text
Reason: OOMKilled
Exit Code: 137
```

Then:

```bash
make verify
```

Verification covers Operator logs, the CloudWatch incident log group, S3 evidence, and the DevOps Agent investigation path.

For detailed checks see [TESTING.md](TESTING.md).

## 11. Cleanup

```bash
make destroy
```

Then delete the manually created DevOps Agent Agent Space/webhook if you no longer need them. If you used the temporary EC2 image builder, terminate it after the Operator image is safely in ECR.
